# Spry

Meetings, listed and added. FastAPI + PostgreSQL backend, React + Vite frontend, one repository.

The structure, contracts and versions are specified in **[PROJECT.md](PROJECT.md)** — read that
first. Why it is one repository: [docs/decisions/0001-monorepo.md](docs/decisions/0001-monorepo.md).

## Run it

Install Docker Desktop, then:

```bash
docker compose up --build
```

| URL | What |
|---|---|
| http://localhost:5173 | Frontend |
| http://localhost:8000/docs | API docs (Swagger) |
| http://localhost:8000/api/meetings | The list endpoint |

Port taken? Copy `.env.example` to `.env` and change `FRONTEND_PORT`, `BACKEND_PORT` or `POSTGRES_PORT`.

## Everyday commands

```bash
make lint        # ruff + eslint + prettier
make fmt         # auto-format
make test        # backend tests against a real Postgres
make shell-db    # psql
make clean       # stop and wipe the database
make lock        # after changing dependencies: regenerate uv.lock / pnpm-lock.yaml
```

## Deploy

Two roads, one per kind of change:

- **The application** (API image, site): GitHub Actions on every push to `main`
  (`.github/workflows/deploy.yml`, the same `make deploy-backend` / `make deploy-frontend` you can
  run locally). See PROJECT.md §8.
- **The infrastructure** (sign-in, weekly report, agenda parser): Terraform in [`infra/`](infra),
  planned and applied by **HCP Terraform** (organization `ooad-anastasiialem`, workspace
  `spry-dev`). A pull request that touches `infra/` gets a plan as a check, and a merge to `main`
  applies it. Nobody applies from a laptop. Why: [docs/decisions/0005-terraform.md](docs/decisions/0005-terraform.md).

When a change needs both (say, a new environment variable for a Lambda), merge the
infrastructure first, wait for *Apply finished*, then merge the code.

### Infrastructure from a laptop: read and plan only

```bash
brew install hashicorp/tap/terraform   # 1.10 or newer
terraform login                        # once: stores an HCP Terraform API token
make infra-init                        # connect infra/ to the spry-dev workspace
make infra-plan                        # speculative plan, runs in HCP Terraform
make infra-output                      # what exists: pool id, client id, parser URL, ...
make infra-env                         # copy public outputs to .env, print Google/DKIM settings
make auth-branding                     # sign-in page background (after the pool exists)
```

| File | What |
|---|---|
| `infra/auth.tf` | Cognito user pool, Google IdP, web client, managed login, link-accounts trigger |
| `infra/reports.tf` | Schedule → SQS → builder Lambda → S3 → mailer Lambda → SES |
| `infra/ai.tf` | Agenda-parser Lambda, its function URL, the monthly budget alarm |
| `infra/data.tf` | What it reads from the CloudFormation stacks that remain (`backend.yaml`, `frontend.yaml`) |
| `infra/terraform.tfvars` | Non-secret inputs. `google_client_secret` is a sensitive variable in the workspace |

The HCP workspace has `TFC_AWS_PROVIDER_AUTH=true` and `TFC_AWS_RUN_ROLE_ARN` (dynamic
credentials through OIDC, no AWS keys), and the sensitive Terraform variable
`google_client_secret`. CI reads outputs with the `TF_API_TOKEN` repository secret.

## Google Cloud (lab 9)

The core of Spry (site, API, database) also runs on Google Cloud, described in [`gcp/`](gcp) with
its own HCP Terraform workspace `spry-gcp` and its own state. Sign-in (Cognito), the weekly report
and the agenda parser **still run on AWS**; the API on Cloud Run checks the same Cognito tokens.
Choices and their reasons: [ADR 0006](docs/decisions/0006-google-cloud.md). Costs and answers:
[docs/gcp-answers.md](docs/gcp-answers.md).

| Piece | Where |
|---|---|
| Site | Firebase Hosting, `https://<project-id>.web.app`; `/api/**` is rewritten to Cloud Run (one origin, no CORS) |
| API | Cloud Run `spry-api`, the Dockerfile's `runtime` target, scales to zero, runs as service account `spry-api` |
| Database | Cloud SQL PostgreSQL 17 `spry-db`, `db-f1-micro`, 10 GB SSD, reached through the Cloud SQL connector socket |
| `DATABASE_URL` | Secret Manager `spry-database-url`, generated by Terraform, read only by `spry-api` |
| Images | Artifact Registry `<region>-docker.pkg.dev/<project-id>/spry` |

### First time

1. Create the project (id `spry-anastasiia-2026`, or change it in `gcp/terraform.tfvars`,
   `gcp/bootstrap/terraform.tfvars` and `infra/terraform.tfvars`), link billing, set a budget alert.
2. In HCP Terraform create the workspace `spry-gcp` (working directory `gcp`). Copy the
   organization id and the workspace id (`org-…`, `ws-…`) into `gcp/bootstrap/terraform.tfvars`.
3. With your own account, no key:

   ```bash
   gcloud auth login && gcloud auth application-default login
   make gcp-bootstrap      # Terraform + API service accounts, Workload Identity pool, local state
   ```

4. Put the three `TFC_GCP_*` outputs into the workspace's environment variables. From then on
   HCP Terraform acts as `spry-terraform@…` through Workload Identity Federation.
5. Put the Cognito pool id and client id (`make infra-output`) into `gcp/terraform.tfvars`.
6. `make gcp-init && make gcp-plan`, then apply (merge to `main` if the workspace is VCS-driven,
   `make gcp-apply` if it is CLI-driven). The first apply runs Google's hello container.
7. Add Firebase to the project once: `npx firebase-tools login`, then
   `npx firebase-tools projects:addfirebase <project-id>`.
8. Merge the `infra/` change that lists the `*.web.app` origin (Cognito callbacks, parser CORS).

### Every deploy

```bash
make gcp-deploy-backend    # build linux/amd64, push to Artifact Registry, roll Cloud Run
```

```bash
make gcp-deploy-frontend   # Vite build with relative /api, firebase deploy --only hosting
```

The database starts empty; the container runs `alembic upgrade head` on every start.

### Stop the database (it does not pause by itself)

Set `db_activation_policy = "NEVER"` in `gcp/terraform.tfvars` and apply. `make gcp-db-stop`
stops it at once, but the next apply with `ALWAYS` starts it again. Stopped, it still bills its
10 GB disk (~$1.70 a month). `make gcp-destroy` deletes everything in `gcp/`; the bootstrap
(`terraform -chdir=gcp/bootstrap destroy`) and the Firebase site go separately.
